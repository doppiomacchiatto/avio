### Code audit done on Windows (read-only; **nothing here is verified on a Mac**)
Looks right already:
- `tauri.conf.json` resource `../backend/dist/sf_backend` is the Unix path; `tauri.windows.conf.json` swaps it for `sf_backend.exe` on Windows. `icons/icon.icns` exists.
- `main.rs` picks the backend binary / venv python per OS; `open_file` uses `open` / `xdg-open`; the macOS app menu emits `app:open-about` for the in-app About modal.
- `platform.rs` has a `UnixPlatform` (process-group spawn and kill) for the single-file PyInstaller backend (bootloader + python).
- `platform_env.py` `MacOSProvider` adds Homebrew, nvm, Volta, n, npm-global and Yarn to `PATH`; the data dir is `~/.avio`; `CREATE_NO_WINDOW` falls back to `0`; `/api/open_file` handles `darwin`.
- Frontend path helpers (`joinPath`, `baseName` in `apexExport.js`, the FLS/Profiles "friendly dir") handle both `/` and `\`. `isTauri()` uses `__TAURI_INTERNALS__`, which Tauri sets on macOS too.

Risks to check, in the order you will hit them:
1. **`pyinstaller` is not in `backend/requirements.txt`** (the Windows venv had it installed by hand). A fresh checkout fails at `npm run build:backend` with "No module named PyInstaller". Fix: add `backend/requirements-build.txt` (or add it to requirements), and update the README "Dev setup".
2. **Architecture.** PyInstaller builds for the host CPU, so an Apple Silicon Mac produces an arm64-only `sf_backend`; Intel users need an x86_64 build. A universal `.dmg` would need a universal2 Python + dependencies. Plan on one `.dmg` per architecture (Tauri names them `Avio_1.0.1_aarch64.dmg` / `_x64.dmg`).
3. **Gatekeeper / unsigned.** First launch: right-click → Open, or `xattr -dr com.apple.quarantine /Applications/Avio.app`. Apple Silicon also refuses to run arm64 executables with no signature at all; check `codesign -dv --verbose=4 /Applications/Avio.app/Contents/Resources/sf_backend`. If the OS kills the backend, ad-hoc sign it in the build (`codesign --force --sign - <file>`).
4. **Finder-launched apps have a minimal `PATH`.** Confirm `sf` and `node` are found for each install style (Homebrew, nvm, official installer): the 🐞 Debug log and `/api/sf-version` show the path it picked. `platform_env.py` is meant to cover this.
5. **Orphan processes.** After Quit / the close-confirm dialog, `pgrep -fl sf_backend` must be empty.
6. **Native bits in WKWebView:** Save and folder dialogs, About menu item (Avio → About), Cmd+Q vs window close, Ko-fi / sf CLI links (`openExternal`), dark mode.

```powershell
# build + install (stops a running Avio first). ~5 min; run in the background with a log.
```

## Things that will bite you

- **Venv launchers embed the absolute venv path.** After moving/renaming the project, `Scripts\*.exe` (or `bin/*`) fail silently (exit 1, no output). Use `python -m ...` (`venv-run.mjs` does).
- **`window.__TAURI__` is undefined in the packaged app.** Use `isTauri()` / `openExternal()` from `client.js` or import `@tauri-apps/*` directly. `target="_blank"` links do nothing.
- **Dialog helpers throw on failure; `null` means cancelled.** Always catch and show an error.
- **Scripted edits must preserve CRLF** (working-tree files are CRLF on Windows). Python `read_text()` converts to LF; use `read_bytes()/write_bytes()` for bulk edits.
- **The desktop client only sends GET and POST** through Tauri (`api_get` / `api_post`). A `DELETE`/`PUT` becomes a POST to the same path. Add a POST alias route for anything destructive (see `/api/ai/skills/remove`).
- **`api()` logs every failure** to the debug log. For polling use `waitForBackend()` (quiet).
- **`_sf()` returns CLI error JSON instead of raising.** Always check `status`. Commands that need a project need `cwd=` (temp `sfdx-project.json`); the retrieve/deploy target dir must not overlap the package dir.
- **Never deploy a stub to toggle a validation rule** (it overwrites the formula/message). Use the Tooling API read-modify-write in `toggle_validation_rule`.
- **Skills:** detection reads user messages only; skill text is upstream (`forcedotcom/sf-skills`) and bundled byte for byte. Added skills match on words in the *skill folder/display name*, so a skill named only with generic words (`platform-generate`) is always injected.
- **Python 3.9 support** is claimed: avoid 3.10+ APIs (`tempfile ignore_cleanup_errors`, `zip(strict=)`, `X | None` at runtime without `from __future__ import annotations`).
- **GitHub `/releases/latest` skips pre-releases.** Link to `/releases` until a full release exists.
- **PowerShell 5 mojibake:** set `[Console]::OutputEncoding = [Text.Encoding]::UTF8` before reading files with emoji/em dashes; write files as UTF-8 without BOM.
- **Red `NativeCommandError` after `git push`/`fetch`/`cargo` in PowerShell is harmless** (progress goes to stderr).
- Secrets: the `api_key` file in the Avio data dir is plain text. Never print or log it.
