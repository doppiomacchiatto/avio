# Avio 1.0.4 Beta

**Recommended for everyone on 1.0.3.** Windows 10/11 (x64). macOS and Linux builds are not published yet.

> **Beta software.** Read-only by default: Avio does not change your org unless you explicitly use a write action (for example the validation-rule Disable All / Restore). Try it on a sandbox first.

## What's new since 1.0.3

- **Better Apex from the built-in Apex skill.** The bundled Apex Generate skill tells the AI to start from code templates (service, selector, domain, trigger, batch, queueable, REST resource and others), but those templates were never included, so the AI was pointed at files it never saw. The 17 templates and reference classes are now bundled and sent with Apex requests to cloud models, on every provider. This makes an Apex Runner request larger (about 23,000 tokens instead of about 14,500), which costs a little more per message.
- **Skills fit the model's context.** When Avio knows how much a model can read at once (OpenRouter, the OpenCode gateway and Groq report it), it shortens the Salesforce skills, or leaves them out, when the prompt would not fit, and the **Skills used** line says so. If a provider still answers that the prompt is too long, Avio tries once more with shorter skills and otherwise explains the problem in plain words. Set `skills_context_guard` to `false` in `config.json` to turn this off.
- **Local models are now marked experimental** in these notes (see Known limitations).

## Tested scope

Tested end to end with GPT-6 Luna, Grok 4.7, Gemma 4 31B and Nemotron 3 / 3.5 Super through OpenRouter's US region on a Business account. An Apex test class and test data factory generated by GPT-6 Luna were deployed to a sandbox and their tests passed; other generated code has not been validated by deployment. Review AI-generated Apex before using it, and try it in a sandbox first.

## Requirements

1. **Salesforce CLI (`sf`)** installed and on your PATH: `npm install -g @salesforce/cli`
2. **At least one authenticated org**: `sf org login web --alias myorg` (or use **Log in with browser** in Avio's org picker)
3. *(Optional)* an **AI provider API key**, only for the AI features. Add it under ⚙ Settings → AI.

## Install

1. Download **`Avio_1.0.4_x64-setup.exe`** below. (An `.msi` is also attached for managed deployments.)
2. Run it. Because this build is not code-signed yet, Windows SmartScreen may show **"Windows protected your PC"**: click **More info**, then **Run anyway**.
3. Open Avio, pick an org, and go.

To check the download is the file we published, compare its SHA-256 hash:

## Upgrading

- **From 1.0.2 or 1.0.3:** install over it. Your connections, keys, skills, settings and kept conversations are kept.
- **From 1.0.1:** see the 1.0.2 notes: the first launch moves your API key into the Windows keystore.

## Known limitations

- Windows only in this release; not code-signed
- Built-in skill templates are sent only to cloud models; local models get the condensed rules
- The context check works ahead of time only for providers that report a model's context size (OpenRouter, the OpenCode gateway, Groq); for others Avio relies on the provider's "too long" error and retries once
- Closes that skip Avio's close dialog (Windows shutdown or sign-out, ending the process, a crash) cannot offer to save conversations
- Restore offers only the newest kept conversation per panel; the Apex and SOQL Runner offers appear when that AI panel is open
- Stop was checked against a test provider; whether every vendor stops billing at the moment the connection closes has not been confirmed
- **Local models (Ollama, LM Studio) are experimental.** Avio sends them a condensed version of its Salesforce skills (about 6,000 characters, without the code templates or skills you added), and Ollama's default context window is small, so a long prompt can be cut without warning. Small local models also write noticeably weaker Salesforce code. Use a cloud model for Apex generation; full local support (context checks and a list of recommended models) is planned for a future release.
- AI answers can be wrong. Review generated Apex before you deploy it.
