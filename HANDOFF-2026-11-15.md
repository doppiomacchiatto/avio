### Plan: full local-model support (future release, agreed 2026-11-19; not started)

Local models stay **experimental** until then (stated in the 1.0.3 release notes' known limitations). Gate on **context window, not parameter count**: the Apex skill with templates is ~23k tokens, and Ollama's default `num_ctx` is a few thousand tokens and truncates the middle silently, so a 70B model on the default context fails while a 14B model with 32k works.

1. **Detect:** read the model's maximum context from Ollama's `/api/show` (`model_info` `*.context_length`); LM Studio and other servers: their model metadata where available, else treat as unknown.
2. **Ask for it:** send `num_ctx` (Ollama's OpenAI-compatible endpoint accepts it through `extra_body` `options`; verify) so the server does not fall back to its small default.
3. **Thresholds:** about 32k or more gets full skills; below that condensed skills with a visible warning in the panel; below about 8k refuse with an explanation. Reuse the context guard from `2eefc06`.
4. **Recommended list:** a short, tested list of local models (code-tuned, such as Qwen Coder, roughly 14B and up) shown in Settings, instead of a hard size rule; anything that passes the context check can still be picked.
5. **Detect local servers properly:** treat any Ollama/LM Studio server as local by probing it (for example `/api/version` or `/api/show`), not only by a localhost URL, so a LAN or Docker server is covered.
6. **Tests:** fake Ollama endpoints for `/api/show` and context-length errors; a real run with one recommended model on the developer's machine, including the Apex test-class prompt deployed to `sandbox-org`.

**What changed**
- **Timeout:** `ai_client._load_chat_timeout(url)`: `config.json` `chat_timeout_seconds` (10..3600, junk ignored) else 300 s cloud / 900 s local. `AIClient._client_for` builds the SDK client with `openai.Timeout(connect=15, read=T, write=60, pool=15)` and `max_retries=1` (the cache key includes T). `read` is the longest SILENCE, not the total time. `describe_error` recognises `openai.APITimeoutError` and the raw httpx/httpx2 timeouts that surface mid-stream (matched by class name through the MRO; this environment's openai uses `httpx2`): "No reply from <host> for <model> in 5 minutes, so Avio stopped waiting." plus advice (local: model may be loading; OpenRouter: pick a model with more than one host in your region) and the setting name.

## Original design for chat history (superseded where it differs from the block above)

**Developer's words:** AI chat should persist until the app is closed (done, in memory). Then: warn the user before closing that chat history is not saved, give them a way to save the text locally, and load it the next time they launch. "Chat history is a new requirement."

**Recommendation: yes, warn, but only when there is something unsaved**, and make saving explicit (privacy: chats can contain Salesforce code, query results and org details). Three pieces: a close warning, Save/Load buttons, and an opt-in restore on next launch.

### Facts about the current code (so you don't re-read it)
- **Closing already has a confirmation.** `src-tauri/src/main.rs` (~line 411) `on_window_event`: on `CloseRequested` it calls `api.prevent_close()` and emits `app:close-requested`. `App.jsx` (~line 47) listens, shows the **"Stop background processes?"** modal (~line 514), and on confirm calls `invoke("confirm_close")` (`main.rs` ~line 302: POSTs `/api/shutdown`, kills the backend process tree, exits). **Add the unsaved-chat section to that modal.**
- **Closes that bypass the modal cannot warn:** OS shutdown/logoff, killing the process, the installer's `/S` stopping Avio, a crash. Say so in the docs.
- **Session state:** `frontend/src/sessionStore.js` (`getSession/setSession/clearSession/useSessionState`). Keys: `apex.ai.{messages,input,streaming,streamBuf,truncated,streamSkills,open}`, `soql.ai.*`, `chat.{messages,input,streaming,truncated}`. A message is `{role: "user"|"assistant", content, skills?}`.
- **What is in a conversation:** only user and assistant messages. The *system prompt* (editor code, last debug log lines, object list) is built per request and is **not** in the history. API keys never reach the page, so they can't be in a saved chat. Assistant replies may repeat code or data.
- **File access today:** Tauri commands `write_file(path, content)`, `path_exists`, `open_file` exist; there is **no `read_file`**. `dialog:allow-open` and `dialog:allow-save` are already in `src-tauri/capabilities/default.json`. `client.js` has `openSaveDialog` and `openDirDialog` (native dialogs; they **throw** when unavailable and return `null` when cancelled; **`window.__TAURI__` is undefined in the packaged app**, use `isTauri()` and import `@tauri-apps/plugin-dialog`); there is no open-file helper yet. App data lives in `%APPDATA%\Avio\` (`config.json`, `query_history.db` (SQLite, the SOQL history), `skills\`), Mac `~/.avio`, Linux `$XDG_DATA_HOME/avio`.
- The desktop client only sends GET and POST through Tauri: give any delete a POST alias route.

### Proposed behaviour
1. **Unsaved tracking.** Per surface (apex, soql, chat) keep `revision` (bumped on every change to messages) and `savedRevision`. A conversation is unsaved when it has messages and `revision != savedRevision`. `hasUnsavedChats()` returns the list with message counts.
2. **Close warning** (in the existing close modal, only if `hasUnsavedChats()`): "You have unsaved AI conversations: Apex Runner (6 messages), AI Chat (2). They are lost when Avio closes." Buttons: **Save and close** (saves each unsaved conversation to the app-data folder, then closes), **Close without saving**, **Cancel**. Keep "Stop background processes?" as is. In browser dev mode fall back to `beforeunload`.
3. **Save / Load buttons** in each AI panel header (Apex Runner, SOQL Runner, AI Chat): **Save** opens the native Save dialog (formats: `.json` machine-readable and versioned, and `.md` human-readable); **Load** opens the native Open dialog. Loading into a non-empty conversation asks **Replace / Append / Cancel**. After a load, show "N messages loaded (~X tokens will be sent with your next message)" because loaded history becomes model context and costs tokens.
4. **Next launch: opt-in restore, never silent.** If saved conversations exist for a surface, show a one-line banner in that panel: "Restore your last Apex conversation (saved Nov 15, 10:02 PM, 6 messages)? [Restore] [Dismiss] [Delete]". A later, optional setting "Remember my AI conversations between launches" (default **off**, with a plain-text warning that chats may contain Salesforce data and code) can auto-save with a debounce; include "Delete all saved conversations".
5. **Retention:** keep at most N (suggest 20) saved conversations per surface in the app-data folder, oldest removed; a list with delete.

## AI connections, OS-keystore keys and API token (2026-11-15)

**Design (agreed with the developer: "go" on the recommended defaults):**
- **Keys live in the OS keystore** through Python `keyring` in the backend (`backend/secret_store.py`): Windows Credential Manager, macOS Keychain, Linux Secret Service. No usable keystore (or a value it refuses, e.g. Windows caps at ~1,280 chars) falls back to a private `secrets/<account>.key` file in the Avio data dir and `status()` reports `secure: false` so Settings warns. No endpoint ever returns a key (only `key_set` and the last four characters).
- **Connections** (`backend/connections.py`): `config.json` holds `connections: [{id, label, preset, base_url, model}]` and `default_connection`; the key is at keystore service `Avio`, account `connection-<id>`. REST: `GET/POST /api/ai/connections`, `POST /api/ai/connections/delete`, `POST /api/ai/connections/default` (POST aliases: the desktop client only sends GET/POST). `ChatRequest` and `/api/models` accept `connection`.
- **Resolution** (`connections.resolve`): explicit id → that connection (developer overrides ignored); no id → default connection with any developer override (`opencode.config.json`, `OPENCODE_*` env) applied on top; no connections → the legacy single-key chain. **An override that changes the host never borrows the connection's key**, and `/api/models` only uses a stored key for the connection's own host (so changing the provider dropdown can't leak a key to another vendor).
- **Migration** (`migrate_legacy`, run in the FastAPI lifespan, not at import): an existing `api_key` file becomes a "Default" connection (preset detected from URL, else from the key prefix: `sk-ant-` Anthropic, `oc_sk_` OpenCode, `AIza` Google, `gsk_` Groq, `sk-or-` OpenRouter, `sk-` OpenAI); the plain file is deleted **only after** the keystore returns exactly what was stored. Legacy `model`/`base_url` are removed from `config.json`. Forward-only: **older builds can't read the key afterwards.**
- **UI:** Settings → AI has a connection selector (+ New, Make default, Remove saved key, Delete with a two-click confirm), the existing provider/key/URL/model fields edit the selected connection, and a note says where keys are stored. Apex Runner, SOQL Runner and AI Chat each have a `ConnectionPicker` (shown with 2+ connections; choice remembered per panel in localStorage; shared cache in `frontend/src/connections.js`). The "No API key" message in the panels used to be dead code (text mismatch); they now show the backend's message.
- **Per-launch API token** (security prerequisite): the Tauri shell generates a random token (`getrandom`), passes it to the backend as `AVIO_API_TOKEN`, and exposes it to the page through the `get_api_token` command. The backend requires `Authorization: Bearer <token>` on everything except `/api/health`, `/openapi.json` and `/docs`, `/redoc`, and CORS preflights; `client.js` adds it to every direct fetch (normal calls, the SSE stream, the Profiles export); the Rust proxy commands, restart and shutdown add it too. No token (dev, `npm run dev:backend`) = open, as before. **CORS stays `*` on purpose**: the WebView origin differs per OS and the token, which other origins can't know, is the access control (this closes the old "tighten CORS" item).

## Things that will bite you

- **Venv launchers embed the absolute venv path.** After moving/renaming the project, `Scripts\*.exe` (or `bin/*`) fail silently (exit 1, no output). Use `python -m ...` (`venv-run.mjs` does).
- **`window.__TAURI__` is undefined in the packaged app.** Use `isTauri()` / `openExternal()` from `client.js` or import `@tauri-apps/*` directly. `target="_blank"` links do nothing.
- **Dialog helpers throw on failure; `null` means cancelled.** Always catch and show an error.
- **Scripted edits must preserve CRLF** (working-tree files are CRLF on Windows). Python `read_text()` converts to LF; use `read_bytes()/write_bytes()` for bulk edits.
- **The desktop client only sends GET and POST** through Tauri (`api_get` / `api_post`). A `DELETE`/`PUT` becomes a POST to the same path. Add a POST alias route for anything destructive (see `/api/ai/skills/remove`).
- **`api()` logs every failure** to the debug log. For polling use `waitForBackend()` (quiet).
- **`_sf()` returns CLI error JSON instead of raising.** Always check `status`. Commands that need a project need `cwd=` (temp `sfdx-project.json`); the retrieve/deploy target dir must not overlap the package dir.
- **Never deploy a stub to toggle a validation rule** (it overwrites the formula/message). Use the Tooling API read-modify-write in `toggle_validation_rule`.
- **Skills:** detection reads user messages only; skill text is upstream (`forcedotcom/sf-skills`) and bundled byte for byte. Added skills match on words in the *skill folder/display name*, so a skill named only with generic words (`platform-generate`) is always injected.
- **Python 3.9 support** is claimed: avoid 3.10+ APIs (`tempfile ignore_cleanup_errors`, `zip(strict=)`, `X | None` at runtime without `from __future__ import annotations`).
- **GitHub `/releases/latest` skips pre-releases.** Link to `/releases` until a full release exists.
- **PowerShell 5 mojibake:** set `[Console]::OutputEncoding = [Text.Encoding]::UTF8` before reading files with emoji/em dashes; write files as UTF-8 without BOM.
- **Red `NativeCommandError` after `git push`/`fetch`/`cargo` in PowerShell is harmless** (progress goes to stderr).
- Secrets: the `api_key` file in the Avio data dir is plain text. Never print or log it.
